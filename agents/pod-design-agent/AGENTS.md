# AGENTS.md

**POD Design Agent**. One of the nine Ecom Agents from [github.com/AoThunDao/ecom-agents-public](https://github.com/AoThunDao/ecom-agents-public).

This is the installed kit's own rule file, the one an agent working inside `«DESIGN_ROOT»` reads. It is not the repository's `AGENTS.md`; that one governs people editing the source checkout.

This file follows the [AGENTS.md](https://agents.md) convention so that any harness can pick this kit up without being told how. It is a map, not the instructions. **The instructions are the files it points at, and they are authoritative over anything summarised here.**

## If you have been asked to install this Agent

The person opened you in this folder and said something like "install the POD Design Agent from this folder". Read `INSTALL-PROMPT.md` and follow everything between `=== BEGIN PROMPT ===` and `=== END PROMPT ===` exactly as if they had pasted it. `«DESIGN_ROOT»` is this folder, resolved to an absolute path. Where the `FILL THIS IN` block is unedited, work the lines out yourself the way the prompt says, and ask one question only if you cannot.

## If you have been asked to run a routine

Scheduled jobs use `node scripts/run-routine.mjs <id> -- <harness> [args]` from this kit root. The supervisor holds the run lock; a child already inside it must not start another supervisor. First run the cheap preflight `node scripts/guard.mjs <id>`. Exit on a non-run verdict, which the guard already records. On `run`, read:

1. `CONTRACT.md` - the laws every routine in this kit obeys. Read this even if the task looks small.
2. `ROLE.md` - what this Agent is responsible for and what belongs to someone else.
3. `SCHEDULE.md` - your row. It carries your days, window, period key, budget and browser lane. **Every clock time and every budget figure in this kit lives in that table and nowhere else.** If you find a clock time inside a routine file, that is a defect, not a source.
4. `routines/<id>/SKILL.md` - the routine itself.

Follow the routine opening preflight for `RELEASES.md` and any `POD.md` or `DROPSHIP.md` profile before business work. The guard checks eligibility only. Atomic state replacement protects file integrity; `scripts/run-routine.mjs` prevents concurrent wrapped runs.

Pre-owner refusals are stored separately in `state/runtime-refusals/*.json`. They mean no harness started for that invocation; never treat them as the owning run's terminal record. The member and fleet audit read this evidence alongside runtime journals.

## What this Agent will never do

It renders, verifies, commits generated skills and writes receipts inside the bound folders and leaves every outward action to the person who hired it, unless that person released the channel in `RELEASES.md` at the kit root, in which case the routine that stages the channel completes the action and records it. The one releasable channel here is pushing `skills_branch` in the bound repository. If a task seems to require sending or publishing on a channel that is not released, that is a signal to stop and write a blocker, not to proceed.

It also never edits its own `SCHEDULE.md` row, never widens its own budget, and never invents a number. Every figure it publishes carries the file it was read from and the date it was read.

## Files it owns and files it must not touch

`state/`, `runlog.jsonl` and its own outputs (`requests/`, `generated/`, `out/`, `ledger/`) are written by the routines. `SCHEDULE.md`, `config/` and `RELEASES.md` belong to the person who hired it. `builder/` and every `skills/pod-design-<slug>/` tree are machine-owned, refreshed or regenerated by the routines and never hand-edited. `CONTRACT.md`'s file map is the authority on who writes what.

## If you are working on this kit as source code

Read the `AGENTS.md` at the root of the repository instead. It carries the contribution rules, the checks that must pass, and the no dashes rule that CI enforces.

## What lives here

Two scheduled routines (`design-request`, `design-intake`), each a `routines/<id>/SKILL.md` entered through `scripts/run-routine.mjs`. `CONTRACT.md` owns paths, schemas, and the guardrails. `SCHEDULE.md` owns every time, window, and budget. `RELEASES.md` owns which outward channels the member has released.

## Rules that are not style preferences

- The guard runs first, always: `node "«DESIGN_ROOT»/scripts/guard.mjs" <routine-id>` before any business file is read.
- Generated skill contents are machine-owned. Fix the master data in `generated/<slug>/` and regenerate; never edit inside `skills/pod-design-<slug>/` or a staging tree.
- The vendored builder under `builder/` is machine-owned the same way. The intake refreshes it; nobody edits it.
- A PNG is production-ready only when this run's `verify_png_alpha.py` pass and this run's print QA pass both exist beside it.
- No em dash and no en dash in anything written here, code comments included.
- One run record per routine per period, appended through `scripts/runlog.mjs`.
- `requests/inbox/` is the only intake. Work the file, move the file, ledger the line.
